# Модель угроз и оценка рисков ИБ: инвест-сессии компании

Работа по анализу информационной безопасности процесса еженедельных инвест-сессий компании: интервью с сотрудниками, схема сети, модель угроз и оценка рисков, построенные по методике недопустимых событий (в духе методических рекомендаций ФСТЭК России) с привязкой техник к матрице **MITRE ATT\&CK**.

## Описание проекта

Компания проводит еженедельные инвест-сессии, на которых принимаются решения по операциям на фондовом рынке. Сессии организованы через внутреннюю систему видео-конференц-связи (ВКС) на базе **TrueConf**, материалы к сессиям готовятся департаментом инвестиций и хранятся на общих сетевых ресурсах, итоговые решения оформляются протоколом и рассылаются по почте.

В рамках работы проведено обследование ИТ-инфраструктуры компании (интервью с генеральным директором, директором по инвестициям, техническим директором, системным администратором, сотрудниками бухгалтерии, осмотр серверной и рабочих мест) и на основе собранных данных построена модель угроз безопасности с оценкой рисков и приоритизацией мер защиты.

## Схема инфраструктуры

Инфраструктура включает два сегмента:

* **Головной офис** (`router-go`) — пользователи и администраторы (`user-go-pc-1…n`, `admin-go-pc`) и серверы (`srv-trueconf`, `srv-mail`, `srv-fs`);
* **Офис филиалов** (`router-f1`) — пользователи (`user-f1-pc-1…n`);
* **Удалённые сотрудники** — подключаются к трансляции ВКС через интернет.

## Методология

Анализ построен по подходу «от недопустимых событий»:

1. **Недопустимые события** — критичные для бизнеса последствия (утечка данных, подмена участника конференции, потеря данных).
2. **Системы** — целевые компоненты инфраструктуры (ПК работников, серверная, роутер, удалённые компьютеры).
3. **Уязвимости** — выявленные при обследовании недостатки конфигурации, архитектуры и организационные пробелы (например: материалы на общедоступных сетевых дисках, отсутствие резервного канала связи, неусиленная аутентификация на ВКС, открытое хранение токенов, бесконтрольный доступ в серверную).
4. **Угрозы** — конкретные техники реализации, сопоставленные с идентификаторами **MITRE ATT\&CK** (например, T1485 — уничтожение данных, T1486 — шифрование данных, T1499 — DDoS приложения, T1113 — снятие скриншотов).
5. **Модель угроз и оценка рисков** — сведение недопустимых событий, систем, угроз и уязвимостей с указанием типа нарушителя (внешний/внутренний), вероятности реализации и приоритета мер защиты.
6. **Свод по мерам** — сгруппированный по приоритету перечень рекомендуемых мер защиты.

## Ключевые результаты

**Недопустимые события:** утечка данных, подмена участника конференции, потеря данных.

**Наиболее критичные риски (приоритет «Немедленно» / «В ближайшее время»):**

|Недопустимое событие|Система|Угроза|Нарушитель|Вероятность|Приоритет|
|-|-|-|-|-|-|
|Нарушение доступности|Роутер / серверная|Уничтожение данных|Внешний|Высокая|Немедленно|
|Нарушение целостности|Серверная|Подмена контента|Внешний|Высокая|В ближайшее время|
|Нарушение конфиденциальности|Удалённые компьютеры|Снятие скриншотов|Внутренний|Высокая|В ближайшее время|

Полная таблица с обоснованием оценок и перечнем мер — в файле `Таблица\_Модель\_угроз\_и\_оценка\_рисков.ods`.

## Использованные инструменты и подходы

* Сбор требований через интервью с ключевыми сотрудниками и наблюдение (walkthrough серверной, рабочих мест)
* Построение схемы сети
* Таблично-матричная модель угроз (недопустимые события → системы → уязвимости → угрозы → нарушители → вероятность → меры)
* Сопоставление угроз технике **MITRE ATT\&CK** для унификации терминологии
